# bh 保号插件

`.bh` 管理 Emby 保号任务，支持 `embyboss` 的 `/myinfo` 抓取与 `custom` 多级按钮流程。配置保存在 `state/bh/baohao_config.json`，兼容旧 BaoHao JSON 字段；启动时恢复定时任务。

## 使用

发送 `.bh` 查看分节帮助与可复制示例。支持 add、badd/batchadd、edit/set、info、list/ls、rm、disable/enable、now、config、bottoken、target、threshold、tpm ul/i。

Cron 支持 5/6 段；`now` 作为添加时间表示每天当前时刻。random 使用分钟或分钟范围。custom 正则必须含日期捕获组，按 100ms 超时执行；反斜杠原样保留，含空格参数用引号包裹。

定时任务按 Cron 聚合，随机延迟后串行执行；同一任务禁止重入，修改、禁用、删除及导入会取消旧任务上下文。手动 `.bh now` 编辑原消息显示进度，完成后回写分页报告。定时只在临期或异常时发送通知，手动始终尝试推送；未配置或 Bot API 失败时明确提示。

`.bh tpm ul` 导出 `baohao_config.json` 并清空 Token/ChatID；回复同名文件执行 `.bh tpm i`，完整校验后原子保存，并永远保留本地 Token/ChatID。文件上限 512KiB。

## 与旧脚本的兼容及修正

- 保留原字段、命令别名、自动/手动到期规则、Bot 用户名/链接、批量备注解析、删除范围及名称匹配。
- 标准回复支持“上次活动/上次观看/活跃状态”，识别天数或固定到期日期；新规则替换旧规则，未返回规则时保留历史规则。
- 报告文案与旧 bh.ts 逐字对齐：`📊 <b>保号检测聚合/单点报告</b>` 标题、`时间: YYYY/MM/DD HH:mm:ss`、账号名渲染为可点击的 `t.me` 加粗链接、`将在 N 天后禁用`/`已过期 / 可能被禁用`/`抓取失败但历史推算安全`/`时间解析异常` 四类分支，以及 `✅ 全部安全` 与 `<i>(另有 N 个账号状态正常 🟢，已隐藏)</i>` 脚注。安全账号仍然隐藏并汇总，抓取失败仍按历史数据推算。
- 通知与进度消息均按 HTML 分页，按整行装箱，避免把 `<a>`/`<i>` 标签切断；账号名与错误文本只转义 `&`、`<`、`>`，与旧版一致地保留引号。
- 5/6 段 Cron 与带空格引号参数均支持。无效参数、Cron、正则、导入配置明确报错，不再静默成功。
- 新回复既可新增消息，也可编辑同一消息；每级按钮只接受新的界面状态，最终 callback toast 也可作为结果。不会把旧时间当本次成功。
- 编辑、禁用、删除、导入取消旧执行；旧执行不会覆盖新配置。原消息报告失败最多重试三次，仍失败或 Bot 未发送则记录到任务详情。
- 导入始终保留本地秘密，即使备份携带了不同 Token/ChatID；不复制备份中的秘密。

## 验证

本地测试文件按仓库规则忽略，不进入发布包。测试覆盖命令帮助示例、实际 Handle→后台 worker 的两种模式、多级按钮与旧消息拒绝、Bot API 成功/失败、导入/导出、队列取消、防重入、持久化与过期规则。自动化测试通过模拟 Telegram Host/Bot HTTP 验证交互，真实验证边界如下。

本轮补充真实 Telegram 验证：使用用户指定的 Emby Bot，标准模式发送 `/myinfo`、自定义模式发送 `/myinfo` 并按正则解析，均取得真实上次活动时间并更新原消息报告。多级按钮流程已实际点击，但该 Bot 的对应菜单未提供活动时间，按失败处理；成功多级返回路径由模拟集成覆盖。通知 Token 未配置，真实报告明确提示未发送；Bot API 成功/失败通过本地 HTTP 模拟验证。真实读取触发过 FloodWait，因此默认轮询间隔调整为 1 秒。

默认每 1 秒读取一次 Bot 回复，降低 Telegram 历史消息查询触发 FLOOD_WAIT 的风险；单步骤最长等待 12 秒。

# Go 源码插件完全切换

用户已确认完全切换，不再安装或运行独立进程插件。保留现有未提交功能改动。

插件包采用 protocol_version=2，package="."，根目录 Go 包导出 Open(context.Context, pluginapi.Host, string) (pluginapi.Plugin, error)。Plugin 提供 Handle 和 Close。插件源码保存在部署 plugins/，状态保存在 state/；资源使用 go:embed。源码包不含独立 go.mod/go.work，依赖由宿主 go.mod 固定。

管理操作在暂存目录修改源码，生成静态注册代码，调用 Go 编译宿主，再用不联网的 --check-plugins 检查命令冲突与清单。成功后提交源码目录及二进制，失败回滚。运行时只使用编译注册表，不加载磁盘上的可执行文件；未修改的旧目录显示迁移提示，可逐个卸载或替换，但不会编译或运行。

构建源码来自首次配置的 LAOWANGBOT_SOURCE（本地源码目录）或当前版本对应的 GitHub 标签；后续插件构建复用成功构建的源码快照。主程序 update 从发布标签拉取源码，携带锁定的本地插件，编译后替换；不会更新手动插件。构建需 Go 和 Git，运行不需。Windows 暂不支持源码自编译替换，必须外部构建后停止服务手动替换。回滚恢复二进制及插件源码快照，状态不回退。

TPM 和 update 共享部署构建锁。状态与账号数据不复制到构建区。命令帮助和文档解释版本来源、工具依赖、编译耗时、失败保留旧程序及旧包迁移方式。

验证：源码安装/更新/卸载与失败回滚、实际 Go 编译与重启后的内置命令、旧包拒绝、资源与状态保留、冲突与路径校验；运行全量单元测试、integration 标签与覆盖率。

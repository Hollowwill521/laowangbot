# 内置插件功能核查（0.1.10）

范围是官方内置的 Monitor 和 QDSG，以及宿主的插件帮助、输出、消息事件和能力声明。测试代码及数据只保留本地，不进入源码仓库或 Release。

## 执行验证

| 功能 | 验证方式与结果 |
| --- | --- |
| 两个插件的帮助 | 通过实际插件工厂、宿主 runtime、消息事件及 Telegram HTML 解析验证空命令/help；验证 `.help`、`--help` 使用完整帮助及自定义前缀 |
| 长输出 | 验证中文、emoji、HTML 特殊字符、大量任务/配置分段；不丢失正文或第一页，发送失败中止并报错 |
| Monitor 配置 | 执行全部设置族、合法与非法参数、增删改查、开关、保存失败回滚、重启读取 |
| Monitor 匹配 | 覆盖关键词、正则、群/排除群、指定人、管理员/用户/机器人身份、抽奖提取、多个去重依据 |
| Monitor 通知/同步 | 模拟宿主执行转发和保护消息降级、多个目标、延迟发送、备用群、同步回声抑制、重复事件、删除及发送失败 |
| Monitor Bot API | 本地 HTTP 服务验证回调鉴权、offset、换 Token、409 冲突退避、403、无效 JSON、断线重试 |
| QDSG 命令/调度 | 执行创建、批量修改/删除/启停、配置、列表、手动入队、定时/随机延迟、重试、取消和存储失败回滚 |
| QDSG 八种模式 | 模拟宿主执行 text/reply/inline/imagechoice/xigua/math/appcf/moon，验证消息新鲜度、按钮动作及最终状态 |
| QDSG AI/OCR/CF | 本地 HTTP 验证 OpenAI/Gemini/custom 的路径、认证和图片请求；子进程验证 OCR 通信及错误；模拟云端与本机信箱验证 CF proof、结果和清理 |
| QDSG 手动反馈 | 从 Handle(now) 到工作线程执行、重试和完成，原消息聚合编辑；初次编辑失败不入队；手动执行不发送收藏夹通知 |
| QDSG 回调结果 | 验证明确成功/失败的 Telegram 按钮弹窗；普通提示继续等待，否定成功不能判为成功 |

本轮单元、集成及 race 检查通过；Monitor 语句覆盖率 84.1%，QDSG 81.2%。宿主新增回归覆盖帮助注册和输出分页，不表示整个宿主已全面覆盖。全仓库构建及静态检查通过。

## 真实 Telegram 联调

在用户提供的运行环境，对已有 inline 任务进行真实验证：

1. `/start` 返回带“🎯 签到”的内联键盘。
2. 点击按钮后，机器人仅返回弹窗“您今天已经签到过了”，消息历史不发生变化。
3. 修复前忽略弹窗文本，错误等待新消息并超时。
4. 修复后通过 `Handle(now) → 工作线程 → Telegram 点击 → 回调结果`，原执行消息按“已排队 → 执行中 → 完成”编辑三次，实际点击一次，向收藏夹发送零条消息。
5. 执行结果成功落盘；诊断期间正常服务暂停，诊断后恢复原服务。没有将临时诊断程序作为正式部署程序。

## 验证边界

模拟测试证明指定输入及失败路径下的插件行为，不等于所有外部机器人协议都已真机验收。该环境尚未配置 Monitor 关键词/通知目标/Bot Token，也未配置 QDSG AI 密钥或 CF 外援；这些服务没有真实联网验收。本地 OCR 子进程协议已验证，真实 OCR 模型准确率未验证。

定时任务没有原始手动执行消息，继续遵循 notify 配置；手动 now 使用原消息反馈。Monitor 保留通知前写入去重记录的原行为，网络失败不保证所有目标最终收到。线上发送完成后本地存储失败不能撤销已发生的外部操作。
